# TCX Running Analyzer

**Локальный анализ беговых тренировок из TCX любых поддерживаемых устройств → компактный JSON для ИИ и статистики**

[English README](README.md) · [Формат JSON](docs/JSON_FORMAT.md) · [Правила и скилы для агентов](agent/README.md) · [Лицензия MIT](LICENSE)

Утилита анализирует экспортированные файлы **TCX** для беговой дорожки и улицы: определяет беговые отрезки и паузы, вычисляет ЧСС, каденс, восстановление и контроль качества измерений. Работает **без Интернета**, Python **3.10+**, **без сторонних библиотек**.

**Если указать папку, будет создан один общий JSON со всеми тренировками и общей статистикой.** Исходные TCX остаются неизменными.

## Возможности

- **Беговая дорожка и улица:** определение режима по GPS или подтверждённым параметрам, километровые/мильные сплиты, GPS-темп, высота и отдельный учёт предполагаемых пауз.
- Защита сводной статистики от повторных экспортов одного TCX Activity ID при сохранении всех индивидуальных отчётов и диагностике конфликтов.
- **Координаты GPS не попадают в JSON**: используются только внутри анализатора. Подробнее: [Outdoor Running и GPS](docs/OUTDOOR_RUNNING.md).

- Автоматическое распознавание 5×7, 3×10, 2×15, 30 минут непрерывно и других форматов тренировок по каденсу и границам кругов TCX.
- Пульс: средний во время бега/всей активности, максимум, первая/вторая половина, каждые 5 минут, последние 30 секунд, восстановление.
- Каденс в **шагах в минуту**, анализ его динамики.
- Пробежка на дорожке: необязательное значение фактической дистанции и установленной скорости для оценки погрешности данных устройства.
- Пакетная обработка директории, включая подпапки; **один итоговый JSON** со всеми индивидуальными отчётами.
- Диагностика с разделением сообщений `warning` и `info`; скачки ЧСС с точным временем, величиной и фазой тренировки.
- Эвристическая оценка уверенности распознавания каждого отрезка (`high`, `medium`, `low`, `manual_override`).
- Проверка полноты архива по списку ожидаемых TCX и вывод больших промежутков между датами.
- Необязательные дополнительные факты по тренировкам: дистанция, скорость, источник ЧСС и субъективные ощущения.
- **PowerShell-скрипт в корне** и стандартная Python-структура `src/`.

## Автоматический процесс с ИИ-агентом (v1.3.0+)

**Основной сценарий:** пользователь передаёт ИИ один или несколько файлов TCX. Агент **сам запускает анализатор**, изучает JSON, спрашивает только о важных неизвестных ощущениях или показаниях дорожки, сохраняет подтверждённые ответы и автоматически обновляет общую историю. Пользователю не нужно вручную преобразовывать TCX, если агент имеет доступ к папке и запуску программ.

Локальная папка `local-data/` содержит оригиналы `tcx/`, технический `running-activities.json`, накопительные личные сведения `running-metadata.json` и объединённую историю `running-history.json`. Она исключена из Git. Из TCX невозможно восстановить ощущения или достоверно определить тип датчика, поэтому ИИ **не заполняет** эти поля догадками.

Агент выполняет команды (или пользователь вручную для проверки):

```powershell
.\Running-Workflow.ps1 -Ingest -Workspace '.\local-data' -UtcOffset '+04:00' -Paths 'C:\Projects\Бег\TCX\activity_123.tcx'
# После получения ответов пользователя ИИ формирует подтверждённый JSON-патч:
.\Running-Workflow.ps1 -Record -Workspace '.\local-data' -File 'activity_123.tcx' -Patch '.\local-data\confirmed-feedback.json'
```

После первого импорта часовой пояс берётся из сохранённых настроек; `-UtcOffset` можно опускать. `-Record` бережно дополняет метаданные без потери прежних сведений, затем обновляет общую историю. Для принудительной пересборки: `-Rebuild`. Полная схема и ограничения: [Инструкция для агента](docs/AGENT_WORKFLOW.ru.md), [подключение скилов](agent/README.md). **Обычный чат без доступа к локальным файлам не может обновить папку на твоём компьютере автоматически.**

## Бег на улице — новый режим v1.4.0

```powershell
.\Analyze-Tcx.ps1 `
    -Path 'C:\Projects\Бег\OutdoorSamples\ggps-py\data' `
    -ActivityMode auto `
    -Output 'C:\Projects\Бег\OutdoorSamples\outdoor-v1.4.0.json' `
    -UtcOffset '+00:00'
```

В режиме `auto` GPS-координаты указывают на вероятную уличную тренировку; подтверждённые данные дорожки — на `treadmill`. Если оснований недостаточно, тип остаётся `unknown`. В индивидуальных метаданных можно задать `"activity_mode":"outdoor"` или `"activity_mode":"treadmill"`.

**Отдельно учитываются** истекшее время, сумма таймеров кругов TCX, предполагаемые паузы и время бега без этих пауз. По одному TCX нельзя доказать, что пауза была именно Auto Pause. Дистанционные круги TCX не считаются автоматически интервалами бег/ходьба. GPS-темп относится ко всей активности с ходьбой, а не только к беговым отрезкам.

Начиная с v1.4.0, в сводке папки повторный экспорт одного и того же TCX Activity ID (с согласующимися временем и дистанцией) учитывается один раз. Сам файл и его индивидуальный отчёт остаются неизменными. Поэтому агрегаты уличного архива могут отличаться от v1.3.0.

Техническая документация: [Outdoor Running и GPS](docs/OUTDOOR_RUNNING.md) · [обновление на v1.4.0](docs/UPGRADE_v1.4.0.md).

## Запуск без установки Python-пакета

Нужен Python 3.10 или новее. Распакуйте репозиторий, откройте PowerShell в корневой папке проекта.

**Один TCX:**

```powershell
.\Analyze-Tcx.ps1 -Path 'D:\Running\activity.tcx' -TreadmillKm 3.82 -RunSpeedKmh 6.0 -UtcOffset '+04:00'
```

Результат: `D:\Running\activity.running.json`.

**Папка TCX → один JSON для всей папки:**

```powershell
.\Analyze-Tcx.ps1 -Path 'D:\Running' -UtcOffset '+04:00'
```

Результат: `D:\Running\running-activities.json`. Внутри будут все найденные тренировки, их подробный разбор и общая сводка.

**Папка с подпапками и явным путём к JSON:**

```powershell
.\Analyze-Tcx.ps1 -Path 'D:\Running' -Recursive -Output 'D:\Reports\all-runs.json' -UtcOffset '+04:00'
```

При известной скорости бега добавьте `-RunSpeedKmh 6.0`. Значение **не определяется достоверно по показаниям TCX**, задаётся пользователем. Для одного файла можно указать фактическую **общую дистанцию дорожки** `-TreadmillKm`.

**Важно:** для папки `-TreadmillKm` не используется — разные тренировки имеют разные дистанции. Для индивидуальных значений можно указать файл метаданных:

```powershell
.\Analyze-Tcx.ps1 -Path 'D:\Running' -Recursive -Metadata '.\my-metadata.json' -Output '.\history.json'
```

Пример формата: [`examples/metadata.example.json`](examples/metadata.example.json). Укажите в объекте `files` реальные имена TCX и их дополнительные данные. В нём же разрешено вручную записать ощущения (`subjective`). Данные о боли и усталости **никогда не угадываются по TCX**.

### Ручная корректировка интервалов одного файла при обработке папки

В `my-metadata.json` можно указать `run_windows` для конкретного TCX — **в секундах от начала записи активности** или строкой временных диапазонов:

```json
{
  "files": {
    "unusual.tcx": {
      "run_windows": [
        {"start_s": 300, "end_s": 600},
        {"start_s": 660, "end_s": 960}
      ],
      "hr_source": "wrist_optical"
    }
  }
}
```

То же самое можно указать как `"run_windows": "00:05:00-00:10:00,00:11:00-00:16:00"`. Эти интервалы заменят автоматическое распознавание **только для файла `unusual.tcx`**. Не следует задавать их наугад: при сомнениях проверяйте исходный TCX.

### Проверка полноты архива

Подготовьте список ожидаемых имён TCX — JSON (`{"expected_files": ["one.tcx", "two.tcx"]}`) или текстовый файл с одним именем на строку. Примеры: [`examples/expected-files.example.json`](examples/expected-files.example.json), [`examples/expected-files.example.txt`](examples/expected-files.example.txt).

```powershell
.\Analyze-Tcx.ps1 -Path 'C:\Projects\Бег\TCX' -Recursive `
    -ExpectedManifest '.\expected-files.json' -DateGapDays 7 `
    -Output 'C:\Projects\Бег\JSON\running-activities.json' -UtcOffset '+04:00'
```

В `summary.archive_completeness` появятся `missing_files` и `unexpected_files`. Без списка статус `not_assessed`. В `summary.observed_date_gaps` — большие промежутки между датами; они **не означают автоматически**, что тренировки были пропущены.


## Прямой запуск Python

После установки в режиме разработчика:

```powershell
py -3 -m pip install -e .
tcx-running-analyzer 'D:\Running' --recursive --output 'D:\Reports\all-runs.json' --tz-offset '+04:00'
```

Без установки пользуйтесь `Analyze-Tcx.ps1`.

Полный набор параметров:

```powershell
.\Analyze-Tcx.ps1 -Path 'D:\Running\activity.tcx' -RunSpeedKmh 6 -HeartRateSource polar_h10 -UtcOffset '+04:00'
```

Остальные параметры можно посмотреть:

```powershell
py -3 -m tcx_running_analyzer --help
```

Последняя команда требует предварительного `pip install -e .` либо установки `PYTHONPATH=src`. Без этого просто используйте PowerShell-обёртку.

## Формат результата

Для **одного TCX** JSON содержит все измерения, в том числе массив `runs`, в котором есть показатели **каждого** интервала и пятиминутные сплиты.

Для **папки** формат выглядит концептуально так:

```json
{
  "report_type": "tcx_running_collection",
  "summary": {"activities_succeeded": 20, "total_running_minutes": 600},
  "activities": ["Полный отчёт по тренировке 1", "Полный отчёт по тренировке 2"],
  "errors": []
}
```

В настоящем файле элементы `activities` — полноценные JSON-объекты, а не строки; пример выше только поясняет структуру. Каждый отчёт содержит все сведения, а не только несколько чисел. Дополнительно есть SHA-256 исходного TCX, состояние качества (`quality`) и исходные круги TCX. С версии 1.2.0 поле `quality.issues` содержит уровни `warning` и `info` (неизвестный датчик — информационное сообщение), `quality.hr_abrupt_jumps` фиксирует точное время, величину и фазу скачков ЧСС. `runs[].detection` показывает **эвристическую**, не статистическую уверенность распознавания.

При ошибке чтения отдельного TCX утилита формирует JSON с корректно разобранными тренировками и списком `errors`, но завершает процесс с ненулевым кодом.

Полное описание полей: [docs/JSON_FORMAT.md](docs/JSON_FORMAT.md).

## Правила и скилы для ИИ-агентов — необязательно

Отдельная папка [`agent/`](agent/README.md) содержит:

- правила интерпретации ЧСС, дистанции, каденса, ошибок распознавания и субъективных ощущений;
- скил для анализа одной тренировки;
- скил для сравнения всего архива тренировок;
- новый скил ведения личных метаданных и автоматической пересборки истории.

Эта папка **не участвует в запуске** утилиты. Она полезна, если пользователь отдельно настраивает работу ИИ-агента. В [`agent/README.md`](agent/README.md) описано ручное подключение. В корне также есть [`AGENTS.md`](AGENTS.md), который могут обнаружить совместимые агенты; подключение скилов и разрешения на запуск зависят от среды. Обычный чат автоматически не получает доступ к компьютеру.

## Ограничения

- Часы на дорожке могут ошибаться с расстоянием и темпом. Эталон — дорожка при наличии её измерений.
- Порог каденса и границы кругов — эвристика. Для нетипичных тренировок нужно проверять `runs` и `quality.warnings`.
- TCX не гарантирует информации о подключённом датчике пульса; если источник известен, он отмечается вручную.
- Скрипт не определяет наличие боли, усталость или медицинскую причину изменений пульса.
- Названия и торговые марки устройств принадлежат их правообладателям. Проект не связан с производителями устройств.

### Группировка скачков ЧСС и необычный каденс (v1.2.1)

В `quality.hr_jump_episodes` объединяются соседние резкие изменения ЧСС одного направления; исходные записи `quality.hr_abrupt_jumps` остаются без изменений. Если бег не обнаружен, `quality.unclassified_low_cadence_laps` предлагает круги с необычно низким каденсом для **ручной проверки**, а не автоматически относит их к бегу. Подробности: [JSON_FORMAT.md](docs/JSON_FORMAT.md).

## Переименование и изменение схемы JSON (v1.4.1)

Адрес: https://github.com/smihus/tcx-running-analyzer. В v1.4.0 добавлена поддержка бега на улице, а в **v1.4.1** переименованы Python-пакет, модуль, CLI и универсальные поля расстояния. Старые имена не поддерживаются. Схема JSON изменена на `2.0` именно в v1.4.1. Пересоздайте вычисляемые отчёты из TCX; подтверждённые личные метаданные сохраняйте. См. [инструкцию по переходу](docs/UPGRADE_v1.4.1.md).
