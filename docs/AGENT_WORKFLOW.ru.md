# Сценарий ИИ-агента (v1.3.0)

**Основной сценарий:** пользователь передаёт один или несколько TCX. Агент с доступом к файлам и запуску программ автоматически выполняет обработку, изучает результат, уточняет важные неизвестные данные и сохраняет их. В обычном чате без такого доступа агент может подготовить файлы или инструкции, но не должен утверждать, что обновил локальную папку.

## Структура личного хранилища

```text
local-data/                 # личные данные; исключена из Git через .gitignore
  tcx/                      # оригинальные TCX, без перезаписи
  workflow-settings.json    # часовой пояс, задаётся при первом импорте
  running-activities.json   # только результаты Garmin/анализа, без пользовательских данных
  running-metadata.json     # накопительные подтверждённые сведения пользователя
  running-history.json      # общая история: измерения + пользовательские сведения
```

Папку `local-data` удобно разместить внутри проекта, но безопаснее хранить вне публичного репозитория. При выборе другого пути убедитесь, что он не попадёт в Git. Личные TCX, JSON и отзывы **не публикуются**.

## 1. Получение TCX и автоматический анализ

Из корня проекта, PowerShell (Python 3.10+):

```powershell
.\Running-Workflow.ps1 -Ingest -Workspace '.\local-data' -UtcOffset '+04:00' -Paths 'C:\Projects\Бег\TCX\activity_123.tcx'
```

Можно указать несколько файлов: `-Paths @('one.tcx','two.tcx')` или директорию. Сохранённый часовой пояс используется при последующих запусках, тогда `-UtcOffset` можно опустить. Повторное добавление того же файла не создаст дубль. Если имя совпадает, но содержимое другое, импорт остановится вместо опасной перезаписи.

Анализатор формирует `running-activities.json` и `running-history.json`. Если пользовательских сведений ещё нет, эти файлы содержат одинаковые измерения; `running-metadata.json` не создаётся автоматически из TCX.

## 2. Анализ и уточняющие вопросы

Агент читает результат, проверяет `quality.issues`, интервалы, ЧСС и каденс, затем сверяет доступные ранее ответы с `running-metadata.json`. Спрашивает **только существенные неизвестные факты**: было ли больно, усталость и самочувствие, данные дорожки за **всю тренировку**, подтверждённая скорость бега или реальный источник ЧСС. Известные сведения не спрашивает заново. Если пользователь отказался отвечать или не знает — оставляет значение неизвестным.

## 3. Запись ответов и обновление общей истории

После получения ответов агент составляет небольшой `confirmed-feedback.json` только из подтверждённых значений. Синтетический пример: [`examples/user-feedback.patch.example.json`](../examples/user-feedback.patch.example.json). Запрещено додумывать показатели, ставить `false` вместо «неизвестно» или заменять прежние ответы значением `null`.

```powershell
.\Running-Workflow.ps1 -Record -Workspace '.\local-data' -File 'activity_123.tcx' -Patch 'C:\Temp\confirmed-feedback.json'
```

Эта команда добавляет ответы в `running-metadata.json` (с привязкой к Garmin Activity ID и SHA-256), сохраняет ранее записанные ответы, а затем пересобирает `running-history.json`. Если часть данных противоречит предыдущим ответам, агент должен уточнить исправление, прежде чем записывать его.

При необходимости пересоздать отчёты после изменения метаданных:

```powershell
.\Running-Workflow.ps1 -Rebuild -Workspace '.\local-data'
```

## 4. Анализ динамики

Агент читает `running-history.json` и даёт оценку текущей и сопоставимых прошлых тренировок, отделяя измерения Garmin, вычисленные показатели и субъективные сведения. При повторной обработке ранее сохранённые пользовательские ответы не теряются. Ручные границы бега `run_windows` задаются только после подтверждения, а сомнительные измерения не выдаются за диагноз.

Для macOS/Linux или Python-вызовов без PowerShell приведены команды в [`AGENT_WORKFLOW.md`](AGENT_WORKFLOW.md). Правила агента: [`agent/AGENTS.md`](../agent/AGENTS.md), скилы: [`agent/skills/`](../agent/skills/). Скилы должны быть подключены в среде конкретного ИИ-агента: они не дают чату полномочий самостоятельно.
